# Triplet — дизайн

Дата: 2026-08-24
Статус: утверждён пользователем в диалоге; этот документ — фиксация.

## Проблема

Пользователю нужны одновременно VLESS-прокси для одних приложений и DPI-обход
(класса ByeDPI) для других, при этом остальной трафик — напрямую через
провайдера. Существующие решения дают только один из механизмов за раз либо
требуют двух взаимоисключающих VPN-приложений.

## Продукт

Android-клиент «одна кнопка»: один `VpnService`, три маршрута, назначаемые
по приложениям:

| Приложение | Маршрут | Результат |
|---|---|---|
| выбранные пользователем (напр. Telegram) | VPN | egress — сервер VLESS |
| выбранные (напр. YouTube) | DPI | доступность на сети с DPI-блокировками |
| остальные | Напрямую | egress — провайдер |

Распространение: личное использование (sideload APK). Магазины не цель.

## Проверенные факты (фундамент дизайна)

- **VERIFIED** (док. mihomo, июль 2026): правило `PROCESS-NAME` на Android
  матчит имена пакетов; есть правила `UID`, `AND/NOT`; исходящие VLESS
  (+Reality, xtls-rprx-vision), SOCKS5, DIRECT; REJECT.
- **VERIFIED эмпирически** (пред. проект route-vpn, Phase 1M, OnePlus 13s):
  mihomo как TUN-ядро под Android работает на этом устройстве; sing-box — нет.
- **Требование платформы**: на устройстве активен один VPN-слот → вся маршрутизация
  возможна только внутри одного userspace-ядра за одним TUN.
- Ключ пользователя: `vless://…security=reality&flow=xtls-rprx-vision&type=tcp`
  — обязательный поддерживаемый профиль.

## Архитектура

```text
┌────────────────────── Triplet app (Kotlin, Compose M3) ─────────────────────┐
│ TriVpnService (foreground VpnService, единственный)                          │
│   • TUN: 0.0.0.0/0 + ::/0; LAN/link-local/CGNAT исключены из маршрутов       │
│     (API 33+ excludeRoutes; API 29–32 — fail-closed block-правило ядра)      │
│   • собственный пакет — в addDisallowedApplication (анти-рекурсия)           │
│   • FD туннеля передаётся движку                                             │
│                                                                              │
│ mihomo engine (gomobile AAR, pinned commit, Go-враппер ~100 строк:           │
│                 Start(config)/Stop/SetLogCallback)                           │
│   Правила (генерируются из пользовательских назначений):                     │
│     AND(PROCESS-NAME ∈ vpnApps)                    → vless-out               │
│     AND(PROCESS-NAME ∈ dpiApps, NETWORK=udp, DST-PORT=443) → REJECT          │
│     PROCESS-NAME ∈ dpiApps                         → socks5 127.0.0.1:$p     │
│     MATCH                                          → DIRECT                  │
│                                                                              │
│ ByeDPI (MIT; нативный бинарник per ABI в jniLibs, ProcessBuilder)            │
│   слушает только 127.0.0.1:$p; жизненный цикл = цикл сервиса                 │
└──────────────────────────────────────────────────────────────────────────────┘
```

### Решения и их основания

1. **Одно ядро mihomo** — единственный компонент с документированным
   package-matching на Android и доказанной работой на устройстве пользователя.
2. **ByeDPI без своего JNI/C-кода**: готовый бинарник из jniLibs
   (`android:extractNativeLibs`), запуск дочерним процессом, loopback-bind.
3. **Генератор конфига — чистая функция** `(Settings, AppRoutes) → YAML`.
   Главный тестовый контур приложения (золотые тесты) без устройства.
4. **DNS**: hijack :53 внутри туннеля → mihomo DNS с DoH-upstream
   (`https://1.1.1.1/dns-query`). VLESS-маршрут: домен уходит на сервер;
   DPI-маршрут: резолвит сам ByeDPI. Пользовательских настроек DNS нет.
5. **UDP-политика**: VPN-маршрут — UDP поверх VLESS разрешён; DPI-маршрут —
   весь UDP REJECT (ByeDPI TCP-only; fail-closed вместо тихой утечки),
   QUIC-block принуждает YouTube к TCP-fallback; Direct — как есть.
6. **LAN вне продукта**: приватные префиксы исключены из TUN; работает
   нативная модель разрешений Android для локальной сети.
7. **Минимум каркаса**: без Hilt/DI-фреймворков (ручной граф в Application),
   без Room (DataStore: preferences + JSON карта пакет→маршрут), без
   navigation-compose (3 верхних экрана, простой внутренний навигатор).

### Компоненты

| Компонент | Ответственность | Интерфейс |
|---|---|---|
| `TriVpnService` | permission/TUN/жизненный цикл, foreground-нотификация | start/stop интенты; StateFlow статуса |
| `MihomoEngine` (Go) | потребление FD, применение правил, логи | `Start(cfg string) error`, `Stop()`, callback логов |
| `ConfigGenerator` | чистая функция настроек в YAML mihomo | `(VlessProfile?, presets, routes) → String` |
| `VlessKeyParser` | разбор/валидация `vless://` (Reality+vision+tcp) | `parse(uri) → Profile / ParseError` |
| `DpiBackend` | запуск/остановка бинарника ByeDPI, health-check порта | `start(preset)`, `stop()` |
| `RouteStore` | персистентность назначений приложений и настроек | DataStore; Flow + suspend setters |
| `AppInventory` | список установленных приложений (PackageManager) | `Flow<List<AppInfo>>` |
| UI (3 экрана) | Главная / Приложения / Настройки | Compose M3 |

### Экраны

1. **Главная**: большая кнопка подключения; статус `Отключено / Подключение /
   Активно / Ошибка: <причина>`; сводка «N приложений → VPN, M → DPI».
2. **Приложения**: поиск по имени/пакету; у каждого — сегмент выбора
   `Напрямую | VPN | DPI`. Изменения при активном соединении → авто-рестарт
   туннеля (~1 с).
3. **Настройки**: вставка `vless://` с мгновенной валидцией и понятной ошибкой;
   выбор DPI-пресета («Рекомендуемый», «Совместимый»); просмотр последних
   событий сервиса (секреты и URI вырезаны).

Нижняя навигация на 3 пункта. Светлая/тёмная тема Material 3 (следует системе).
Язык интерфейса: русский + английский (строки в ресурсах).

## Потоки данных

- Старт: кнопка → permission check → `DpiBackend.start()` → генерация YAML →
  `MihomoEngine.Start()` → сервис создаёт TUN c FD → статус Active.
- Ошибка старта ключа/движка → одна повторная попытка → состояние Error с
  причиной на главной. Бесконечных реконнектов нет.
- Смена Wi-Fi↔LTE → пересоздание туннеля автоматически.

## Обработка ошибок (конечный автомат)

`Disconnected → Connecting → Active | Error(reason)`
Причины: нет разрешения VPN; невалидный/неподдерживаемый ключ; порт занят;
сервер недоступен (probe-ошибка); краш движка (лог последней причины).
«Активно» = TUN и ядро работают; здоровье VLESS подтверждается проверкой
`generate_204` через loopback mixed-inbound движка (собственный пакет в TUN не
попадает по определению, поэтому сквозная проверка идёт через локальный порт
mihomo тем же путём vless-out). DPI-пресеты — два фиксированных набора
аргументов ByeDPI; конкретные значения фиксируются планом реализации и
проверяются приёмкой на сети с блокировками.

## Не входит в объём

Подписки, другие протоколы (VMess/SS/Trojan/WireGuard), профили/фейловер,
спидтест, статистика трафика, аккаунты/телеметрия/реклама, скрипты, raw-JSON
редактор, произвольные аргументы ByeDPI, iOS/desktop, root-режим.

## Тестирование

- JVM unit: парсер ключа (happy/битые/неподдерживаемые поля), золотые YAML-тесты
  ConfigGenerator (включая QUIC-block правило и дефолт MATCH,DIRECT),
  политика применённых изменений.
- Эмулятор API 36: установка, старт, direct-трафик, рестарт конфигурации.
- OnePlus (приёмка): одновременно Telegram→egress IP VLESS-сервера,
  YouTube→видео играет (DPI), браузер→egress провайдера; LAN недоступен из
  VPN-приложения; анти-рекурсия; смена сети; kill и перезапуск процесса.

## Среда разработки

NixOS: `shell.nix` (JDK 17+, platform-tools, SDK, Go, gomobile/NDK).
minSdk 29, compile/target 36. Движок собирается скриптом `engine/build.sh`
из pinned-коммита mihomo → AAR, подключается локально.
